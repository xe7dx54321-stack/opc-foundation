# Foundation Control Center 运行手册

更新时间：2026-06-25
状态：M3B-3 Ready（真实运行数据接入）
版本：1.1

## 1. 这是什么（小白解读）

Foundation Control Center 是一个可视化中控台，用网页的形式让你一眼看清：

- opc-foundation 有哪些能力
- 每个能力怎么配置、怎么运行
- 每个能力运行得怎么样（健康/降级/失败）
- 失败了怎么排查

就像是汽车的仪表盘，让你随时掌握整个系统的运行状态。

**核心原则：Foundation provides infrastructure. Business systems keep judgment.**

这个中控台只展示基础设施状态，不包含任何投资判断功能。

## 2. 怎么启动

### 2.1 前置条件

确保你已经安装了依赖：

```bash
pip install streamlit pyyaml
```

### 2.2 启动命令

在项目根目录下运行：

```bash
streamlit run src/opc_foundation/dashboard/app.py
```

启动后会自动打开浏览器，默认地址是 `http://localhost:8501`

### 2.3 常见启动问题

| 问题 | 原因 | 解决方法 |
|---|---|---|
| `streamlit: command not found` | 没装 streamlit | 运行 `pip install streamlit` |
| `ModuleNotFoundError: No module named 'opc_foundation'` | 没装项目包 | 在项目根目录运行 `pip install -e .` |
| 浏览器没自动打开 | 浏览器设置问题 | 手动访问 `http://localhost:8501` |

## 3. 页面说明

中控台共有 9 个页面，全部中文界面：

### 3.1 总览

一句话：快速了解整个系统的全貌。

展示内容：
- 能力总数、成熟度分布（可试运行 / MVP完成 / 降级）
- 运行健康分布（失败 / 未知 / 未配置）
- 需要关注的能力数量
- 已使用 / 未使用的能力数量

**什么时候看这个页面：** 每天早上打开，快速扫一眼有没有红色警报。

---

### 3.2 能力地图

一句话：用大白话告诉你每个能力是干啥的。

展示内容：
- 按主线分组（研究信息采集、官方公告采集、文档内容抽取、共享运行工具）
- 每个能力一张卡片，包含：
  - 能力名称和成熟度标签
  - 一句话描述
  - 能干啥（3-5 条要点）
  - 典型用途
  - 输入类型
  - 输出文件路径

**什么时候看这个页面：** 想了解某个能力能干啥、属于哪个模块的时候。

---

### 3.3 能力详情 ⭐（M3B-3 增强）

一句话：每个能力的完整"使用说明书" + 真实运行摘要。

M3B-3 之后，能力详情页不仅有使用说明，还会展示从真实运行数据中聚合的运行摘要。

包含：

#### 顶部信息
- 能力标题和 capability_id
- 负责的 Agent
- 成熟度标签
- 当前运行状态（从真实数据聚合，M3B-3 新增）

#### 运行摘要（M3B-3 新增）
- 最近运行时间
- 最近成功时间
- 最近失败时间
- 连续失败次数
- 失败队列积压数量
- 最近 3 次运行状态
- 最新错误信息
- 最新报告链接（如果有）

#### 能做什么 / 不能做什么
- ✅ 能做什么：这个能力的功能范围
- ❌ 不能做什么：边界和限制（重要！避免误用）

#### 配置说明
- 配置模板文件（参考用）
- 本地配置文件路径（实际运行用）
- 如果本地配置不存在，会提示你从模板复制一份

#### 运行命令
- 校验配置：检查配置文件对不对
- 试运行：不保存数据，先看看有多少候选
- 正式运行：真正执行采集/抽取
- 查看源健康状态：看每个源的运行情况
- 生成报告：生成汇总报告
- 重试失败项：把失败队列里的任务再跑一遍

每条命令都可以直接复制到终端执行。

#### 输出文件路径
- 主输出文件
- 健康状态文件
- 运行日志文件
- 失败队列文件
- 报告目录

每个路径旁边都有 ✅/❌ 标识，告诉你文件是否存在。

#### 常见失败类型
表格形式展示：
- 错误类型（英文标识，方便搜索）
- 含义（中文解释）
- 排查方向（告诉你该检查什么）

#### 排查步骤（按顺序）
一步步告诉你出了问题该怎么查：
1. 先做什么
2. 再做什么
3. 最后做什么

按顺序来，一般都能定位到问题。

#### 相关文档
- 该能力的所有文档链接
- 同样有 ✅/❌ 标识

**什么时候看这个页面：**
- 想运行某个能力，不知道怎么配
- 某个能力出问题了，想排查
- 想了解某个能力的完整信息

### 3.4 项目工作流

一句话：展示下游项目怎么使用 foundation 能力。

展示内容：
- 项目 → 工作流 → 阶段 → Agent → 能力 的完整映射
- 每个工作流的整体健康状态
- 每个能力的运行情况

**什么时候看这个页面：** 想了解某个业务项目依赖哪些 foundation 能力的时候。

---

### 3.5 健康监控 ⭐（M3B-3 增强）

一句话：所有能力的真实运行健康状态总表。

M3B-3 之后，健康数据不再是笼统的整个 archive 状态，而是通过 **runtime binding** 精确匹配每个能力的真实运行记录。

展示内容：
- 顶部 7 个统计卡片（运行正常、降级、失败、需关注、过期、未知、未配置）
- 搜索和筛选栏（按 capability_id / 名称、track、健康状态等）
- 能力列表表格，包含：
  - 能力 ID 和名称
  - 运行健康状态（从真实运行数据中聚合）
  - 最新状态
  - 最新运行时间
  - 最近 3 次运行状态（圆点图）
  - 最近 3 次失败状态（圆点图）
  - 连续失败次数
  - 失败队列积压数量
  - 最新错误信息
  - 建议动作（中文提示）

**什么时候看这个页面：** 系统出问题了，想快速找到哪个能力挂了。

> **小提示：** 「未配置」表示没有 runtime binding（通常是工具类能力），「未知」表示有 binding 但还没运行过。这两个都不是错误，是正常状态。

**什么时候看这个页面：** 想了解某个能力最近运行了几次、成功率如何的时候。

- 每条记录包含：来源 ID、来源类型、项目标识、错误类型、错误信息、重试次数、创建时间

**什么时候看这个页面：** 想知道具体哪些任务失败了、为什么失败的时候。

一句话：所有文档的快速入口。

展示内容：
- 核心文档列表
- 能力相关文档列表
- 每个文档都有 ✅/❌ 标识，表示文件是否存在

**什么时候看这个页面：** 想找文档的时候，不用翻目录了。

---

### 3.9 配置检查 ⭐（M3B-3 增强）

一句话：一键检查所有配置是否正确。

包含 6 项检查：

1. **能力注册表校验**
   - 检查 capability_id 是否唯一
   - 检查每个能力的 track 是否存在
   - 通过会显示"共 X 个能力"

2. **运行手册校验**
   - 检查运行手册的 capability_id 是否都在能力注册表中
   - 检查运行手册有没有重复 ID
   - 检查覆盖率：是不是所有能力都有运行手册
   - 100% 覆盖会显示绿色对勾

3. **Runtime Binding 检查**（M3B-3 新增）
   - 检查 runtime binding 的 capability_id 是否都在能力注册表中
   - 检查有没有重复的 capability_id
   - 检查哪些 binding 指向的 data 文件不存在（warning，不是错误）
   - 显示已绑定 / 未绑定的能力数量

4. **文档存在性检查**
   - 检查每个能力配置的 docs 路径是否真实存在
   - 缺失的文档会列出来

5. **未使用能力**
   - 列出哪些能力暂时没被任何项目使用
   - 不是错误，只是提示信息

6. **未知引用检查**
   - 检查项目工作流中是否引用了不存在的能力
   - 这个是红色错误，必须修复

**什么时候看这个页面：**
- 刚更新完配置文件，想确认对不对
- 新增了能力，想确认有没有遗漏
- 新增了 runtime binding，想确认配置正确
- 系统出问题，先检查配置

## 5. 常见问题排查

### 5.1 页面打不开

**症状：** 运行 `streamlit run` 后浏览器白屏或报错。

**排查步骤：**
1. 确认 streamlit 已安装：`streamlit --version`
2. 确认在项目根目录运行
3. 确认项目包已安装：`pip install -e .`
4. 查看终端有没有报错信息

### 5.2 所有能力都显示"未配置"

**症状：** 健康监控里所有能力都是灰色的"未配置"。

**原因：** 这些能力没有配置 runtime binding。

**说明：**
- 工具类能力（如 LLM 缓存、ArtifactManifest 等）本来就不需要绑定，显示"未配置"是正常的
- 如果是采集类能力（如 RSS、微信等），需要在 `capability_runtime_bindings.yaml` 中配置 binding
- 配置了 binding 但还没运行过，会显示"未知"而不是"未配置"

**解决方法：**
- 工具类能力：不用管，正常现象
- 采集类能力：参考 [Control Center 运行时数据接入说明](foundation_control_center_runtime_data.md) 配置 binding

### 5.3 配置检查里有红色错误

**症状：** 配置检查页面出现红色错误。

**排查步骤：**
1. 仔细读错误信息
2. 根据错误提示修改对应的 YAML 配置文件
3. 刷新页面（或按 R 键）重新检查

### 5.4 能力详情页的路径都是 ❌

**症状：** 输出文件路径旁边都是红色叉号。

**原因：** 还没运行过这个能力，文件还没生成。

**解决方法：** 按照页面上的命令运行一次，文件生成后就变 ✅ 了。

### 5.5 为什么有的能力显示「未知」

**症状：** 健康监控里有的能力显示蓝色的"未知"。

**原因：** 配置了 runtime binding，但还没有匹配到运行记录。

**说明：**
- "未知" ≠ "失败"，只是说还没运行过，或者运行了但没有匹配到记录
- 刚配置完 binding 还没运行过能力，显示"未知"是正常的
- 运行一次这个能力，刷新页面就会变成健康/降级/失败

**解决方法：**
1. 确认 binding 配置正确（source_types 对不对）
2. 按照能力详情页的命令运行一次这个能力
3. 刷新 Dashboard 页面
4. 如果还是"未知"，检查 data 目录下有没有生成对应的 JSONL 文件

详细排查步骤见 [Control Center 运行时数据接入说明](foundation_control_center_runtime_data.md) 第 6 节。

### 5.6 运行手册覆盖率不到 100%

**症状：** 配置检查提示有能力没有运行手册。

**解决方法：**
1. 记下缺失的 capability_id
2. 编辑 `configs/capability_runbooks.yaml`
3. 添加对应的运行手册条目
4. 刷新页面重新检查

## 6. 配置文件说明

中控台读取以下配置文件：

| 配置文件 | 作用 |
|---|---|
| `configs/foundation_capabilities.yaml` | 能力注册表（有哪些能力） |
| `configs/capability_runbooks.yaml` | 运行手册（每个能力怎么用） |
| `configs/capability_runtime_bindings.yaml` | 运行时绑定（M3B-3 新增，能力与真实数据的映射） |
| `configs/capability_usage_registry.yaml` | 使用关系（哪些项目用了哪些能力） |

新增/修改能力后，更新对应的 YAML 文件，中控台会自动读取。

> **M3B-3 提示：** `capability_runtime_bindings.yaml` 是真实运行数据接入的核心配置，定义了每个能力和 source_type/source_id 的对应关系。详情见 [Control Center 运行时数据接入说明](foundation_control_center_runtime_data.md)。

## 7. 技术细节（给开发者）

### 7.1 代码位置

```
src/opc_foundation/dashboard/
├── app.py          # Streamlit 主应用
├── models.py       # 数据模型（dataclass）
├── loaders.py      # 配置加载器
├── health.py       # 健康状态计算
├── usage.py        # 使用关系分析
└── docs.py         # 文档收集
```

### 7.2 设计原则

- **Fail-soft：** 配置文件不存在或格式错误时，返回空数据，不崩溃
- **只读：** 中控台只读取文件，不修改任何数据文件
- **无投资判断：** 所有模型和页面都不包含 ticker / rating / score 等投资判断字段
- **全中文：** 所有用户可见的界面元素都是中文（capability_id 等技术术语除外）
- **M3B-3 真实数据接入：** 通过 runtime binding 从真实运行数据中聚合健康状态，数据缺失时 fail-soft 显示"未知"或"未配置"

### 7.3 如何新增一个能力到中控台

1. 在 `foundation_capabilities.yaml` 中添加能力定义
2. 在 `capability_runbooks.yaml` 中添加运行手册（推荐）
3. 在 `capability_runtime_bindings.yaml` 中添加 runtime binding（如果有真实运行数据，M3B-3 新增）
4. 刷新中控台页面，自动生效
